# i18n — launcher localization

The iMA Menu launcher (Python / PyQt5) ships with a runtime translation layer.
English is the source language; **Polish (`pl`) is fully translated** and can be
switched on live from **Settings → Language**.

```
iMA Menu/Launcher/
├── i18n.py                  # runtime: catalogues, Qt hooks, live retranslation
├── locales/
│   ├── en.json              # source catalogue (keys == values)
│   └── pl.json              # Polish translation
└── tools/
    ├── i18n_extract.py      # scans the sources for user-facing strings
    ├── build_catalog.py     # regenerates en.json + pl.json (holds the PL map)
    └── test_i18n.py         # headless test-suite (56 checks, + test_i18n_integration.py: 39)
```

---

## 1. How it works

The launcher builds its UI in ~24 000 lines spread over a dozen modules, and the
same widgets often carry *data* (NSS tokens, file names, registry values). Rewriting
every call site would be both huge and risky, so `i18n.py` works on two levels:

**a) Automatic hooks (coverage).** At start-up `i18n.install_hooks()` wraps the
*display-only* Qt setters and constructors:

| Hooked | Not hooked (on purpose) |
| --- | --- |
| `QLabel.setText` / `QLabel(text)` | `QLineEdit.setText` — user input, paths, NSS values |
| `QAbstractButton.setText` / `QPushButton`, `QCheckBox`, `QRadioButton`, `QToolButton`, `QCommandLinkButton` constructors | `QComboBox` items — `currentText()` / `itemText()` are read back into `shell.nss` |
| `QWidget.setWindowTitle`, `setToolTip`, `setStatusTip`, `setWhatsThis` | `QPlainTextEdit` / `QTextEdit` / `QTextBrowser` content — NSS source, README markdown |
| `QGroupBox.setTitle` / `QGroupBox(title)` | `QListWidgetItem.setText` — glyph codes |
| `QLineEdit.setPlaceholderText` | style sheets, object names, icon glyphs (`\uE921`) |
| `QTabWidget.setTabText/addTab/insertTab`, `QTabBar.setTabText` | |
| `QAction.setText/setToolTip`, `QProgressBar.setFormat` | |
| `QMessageBox.information/warning/critical/question/about`, `QInputDialog.*`, `QFileDialog.*` (caption + filter) | |

Every string that flows through a hook is looked up in the active catalogue.
**Unknown strings are returned unchanged**, so a glyph, a path or a user's menu
title is never mangled — the catalogue decides what is translatable.

**b) Live retranslation.** Whenever a hook translates something it remembers
`(widget, setter, original English text)` in a `WeakKeyDictionary`. Switching the
language re-runs all remembered bindings, so the whole UI updates instantly — no
restart, no per-window `retranslateUi()` code. Widgets that paint their own
caption (`NavTabButton`, `CapsuleActionButton`, `VisibilityCard`, `TypePill`)
register through `bind_custom()` / `register_refresh()` instead.

**c) Dynamic strings.** Text built with f-strings (`f"Syncing {n} colors..."`) is
matched by the `patterns` section of the catalogue: `{}` placeholders become
non-greedy regex groups and the captured values are re-inserted into the
translation. Because the *original* English render is what gets stored in the
binding, these strings live-update too.

## 2. API

```python
import i18n
from i18n import _

_("Settings")                                  # -> "Ustawienia"
_("None", "separator")                         # contextual lookup
_("Syncing 5 colors...")                       # pattern match
i18n.ngettext("{} item", "{} items", 3)        # Polish plural rules -> "3 elementy"

i18n.set_language("pl")                        # persist + retranslate everything
i18n.get_language() / i18n.available_languages()

i18n.raw(label, plugin_name)                   # never translate this widget
i18n.set_text_raw(label, nss_title)            # one-shot untranslated setText
i18n.bind_custom(widget, apply_fn, "Plugins")  # widget paints its own caption
i18n.bind_transform(label, "General", str.upper)

i18n.canonical(button.text())                  # "Zamknij" -> "Close"
i18n.same(button.text(), "Close")              # language-proof comparison
i18n.connect(callback)                         # notified after every switch
```

### Rules of thumb

* **Display text** → just write the English literal; the hooks translate it.
* **User data / NSS content / paths / registry names** → `i18n.raw(...)` or
  `i18n.set_text_raw(...)`.
* **Comparing widget text against an English literal** → use `i18n.same(...)` or
  `i18n.canonical(...)`. Existing examples: `ModernDialog.add_button()` detects its
  default *Close* button, `menu_builder_widget._on_filter_changed()` maps the
  *All / Items / Menus / Drafts* filter tags back to their canonical value.
* **Painted captions** → `bind_custom` / `register_refresh` so they survive a switch.

## 3. Catalogue format

```jsonc
{
  "meta":     { "language": "pl", "name": "Polski", "version": 1 },
  "messages": { "Settings": "Ustawienia" },           // exact match
  "contexts": { "separator": { "None": "Brak" } },    // _("None", "separator")
  "patterns": { "Syncing {} colors...": "Synchronizowanie kolorów: {}…" },
  "plurals":  { "{} item|{} items": ["{} element", "{} elementy", "{} elementów"] }
}
```

Current size: **570 messages + 93 patterns**, 100 % translated into Polish.
Missing keys fall back to English, so a partially translated catalogue still works.

## 4. Workflow

```bash
cd "iMA Menu/Launcher"

# 1. see what the UI can display + how much is already translated
python tools/i18n_extract.py --stats
python tools/i18n_extract.py --missing

# 2. add the new strings to PL / PL_PATTERNS in tools/build_catalog.py, then
python tools/build_catalog.py          # rewrites locales/en.json + locales/pl.json

# 3. verify (headless, needs PyQt5; on Linux: QT_QPA_PLATFORM=offscreen)
python tools/test_i18n.py                # catalogue + hooks + live retranslation
python tools/test_i18n_integration.py    # the real launcher widgets (utils/modify_widget)
```

`build_catalog.py` never drops entries: it merges the scanner output with the keys
already present in `locales/en.json`, and its `EXCLUDE` set documents every string
that must stay English (cursor scheme role names, fonts, NSS tokens, combo values
that are read back with `currentText()`, log lines parsed by `nss_error_monitor`, …).

### Adding a new language

1. `cp locales/en.json locales/de.json` and translate the values.
2. Add `("de", "Deutsch", "German")` to `i18n.LANGUAGES`.
3. Rebuild (`python tools/build_catalog.py`) — the picker in **Settings → Language**
   lists every catalogue that exists on disk.

## 5. Packaging

`locales/` is bundled by PyInstaller (`launcher.spec` and the template inside
`build_launcher.py` both list `('locales', 'locales')`, and `i18n` is a hidden
import). At runtime `i18n.locales_dir()` resolves `sys._MEIPASS/locales` when
frozen and the source folder otherwise.

The language is stored in `cache/settings.json` under `"language"` (default `"en"`).
For debugging you can override it without touching the file:

```bash
launcher.exe --lang pl          # or:  set IMA_MENU_LANG=pl
```

## 6. Known limitations

* Combo boxes whose items are read back as data (position, separator, visibility,
  parent menu, action type) intentionally keep their English labels — translating
  them would corrupt `shell.nss`. Their surrounding captions are translated.
* Strings composed at runtime from several fragments (rich-text badges such as
  `Modify: <span…>x</span> <span…>in</span> <span…>y</span>`) are translated only
  when the whole render matches a pattern; the remaining ones refresh the next time
  the view is rebuilt (navigation, refresh, reload).
* `shell.dll` / `shell.exe` (the Nilesoft Shell core) and `ima_updater.exe`
  (C#) are outside this layer — only the Python launcher UI is localized.

## PL — skrót

Warstwa i18n launchera: `i18n.py` + katalogi `locales/en.json` (źródło) i
`locales/pl.json` (tłumaczenie). Hooki Qt tłumaczą teksty wyświetlane (etykiety,
przyciski, tytuły okien, podpowiedzi, placeholdery, zakładki, okna dialogowe),
a widgety przechowujące dane (`QLineEdit`, `QComboBox`, edytory NSS) są celowo
pomijane, żeby nie uszkodzić `shell.nss`. Zmiana języka w **Ustawienia → Język**
działa natychmiast (live retranslate) i zapisuje się w `cache/settings.json`.
Narzędzia: `tools/i18n_extract.py` (skan + brakujące tłumaczenia),
`tools/build_catalog.py` (generowanie katalogów), `tools/test_i18n.py` (testy).
